# TASK C 이미지 추출 검토 화면 전달

## 구현 범위

새 화면은 자료 등록에서 사진 유형을 선택했을 때 표시합니다. 기존 대시보드, 가족·동의 화면, 비교 목록과 Excel 데모는 유지합니다. 실제 AI 추출·확정 API를 만들거나 호출하지 않습니다.

사용자 흐름: 가족과 기준일 확인 → 사진 자료 유형 선택 → 원본 이미지 선택 또는 파일 없이 가상 예제 선택 → 가상 분석 → 약품별 원본 대조·수정 → 확인 완료 또는 보류. 가상 예제는 선택 이미지에서 추출된 값이 아님을 명시합니다.

## 가상 사례

1. 정상 제품 1개: 원본 제품명·성분 함량·1회량·하루 횟수·원본 문구와 신뢰도 표시.
2. 복수 약품: 후보 2개, 둘째 후보에는 성분 2개. 각 후보의 수정·확인이 다른 후보에 영향을 주지 않음.
3. 누락: `record:null`인 제품명 미확인 후보와 함량/투약정보 미확인 후보. 값은 자동 추정하지 않음.
4. 실패: 오류 안내, 같은 사례 재시도, 성공 예제로 변경 가능. 실패 후보를 성공처럼 표시하지 않음.

## 확인과 입력 정책

- 원본 `ExtractionResult.record.user_confirmed=false`는 그대로 보존합니다. 별도의 화면용 초안에서만 `user_confirmed=true`가 되며, 서버 저장·복용상태·정규화·Reconciliation을 변경하지 않습니다.
- 제품명 입력과 원본 대조 체크는 이 Mock 화면의 확인 조건입니다. 그 외 미확인 정보는 비워 둘 수 있으며, 모르면 확인 보류를 선택합니다. 실제 API 수용 조건은 팀장 합의 대상입니다.
- 제품 함량은 성분별 값과 함량 단위로, 1회 투약량은 투약 단위와 분리합니다. 0은 정상 값, 공란은 미확인입니다. 소수는 문자열로 유지하며 숫자 범위의 의료적 판단을 추가하지 않습니다.
- 수정 후 확인 상태는 다시 false입니다. 되돌리기는 해당 후보만 원본으로 복구합니다. 성분을 삭제해도 남은 성분의 원본값 참조 위치를 유지합니다.
- 제품명이 없어서 `record:null`인 후보는 임시 UI 초안으로만 보완합니다. 임의의 공통 MedicationRecord를 만들어 제출하지 않습니다.
- 추출 단계의 NEEDS_CONFIRMATION은 ‘추출값 확인 필요’로 표시하며 D의 ‘최신 자료에서 미확인’과 구분합니다. 확인 버튼은 ‘추출 내용 확인 완료 (로컬)’이고 실제 복용 여부를 뜻하지 않습니다.

## 팀장 통합본과의 연결 위치

읽기 전용 검토 기준은 `codex/a-extraction-contract`의 `4758dea4`입니다. 이 브랜치에는 HIRA B→D→C 요청·Current Intake·타임라인 코드가 있고, 이는 C 원본에 자동 반영되어 있지 않습니다. 통합본의 기존 README/HANDOFF에는 초기 Mock 설명이 남아 있으므로 코드와 구분해야 합니다.

이번 작업은 통합본을 C로 병합하거나 통합본 파일을 덮어쓰지 않았습니다. 통합 시에는 신규 컴포넌트·모델·스타일을 가져오고, 팀장 화면의 사진 자료 영역에만 연결하는 방식으로 검토해야 합니다. C의 `main.tsx` 전체를 통합본에 복사하면 HIRA와 Current Intake를 잃을 수 있으므로 그렇게 적용하지 않습니다.

컴포넌트 입력은 `familyMemberId`, `familyLabel`, `sourceType`, `sourceLabel`, `recordDate`, `file`입니다. 가족·자료·기준일 변경 시 컴포넌트의 key도 새 세션으로 교체해야 합니다. 전송/저장 콜백은 아직 제공하지 않습니다.

## 팀장에게 제안하는 API 초안과 미결정 사항

아래는 제안이며 `docs/API_CONTRACT.md`나 공통 스키마를 변경하지 않았습니다.

- 문서 범위: 가족 ID, 문서/요청 식별자, 출처 유형, 기준일, 요청 취소·중복 처리 기준.
- 후보 범위: 목록과 후보 식별자, ExtractionResult의 status/record/warnings/errors.
- 누락 후보: `record:null`일 때에도 후보 식별자와 허용된 원본 부분값을 어떻게 전달할지 결정 필요. 현재 A adapter는 제품명 누락 시 그 밖의 추출값을 UI에 제공하지 않으므로 재구성하지 않음.
- 수정/확정 범위: 원본과 변경값, 필드별 변경 표시, 후보별 또는 일괄 확인, 필수 입력 조건, revision/중복 확정 정책.
- 다음 처리: 사용자 확인 후 B 정규화 호출 주체·시점과 서버 저장 범위. Current Intake 확인은 별도 절차로 유지.

## 검증과 실행

기본 검증: `pnpm test`, `pnpm build`.

선택적 실제 브라우저 검증은 Playwright가 있는 개발 환경에서 실행합니다. 앱을 먼저 실행하고 다음 환경을 설정합니다.

```powershell
$env:YAKEUM_TEST_URL = 'http://127.0.0.1:4191/'
# Playwright가 일반 모듈 경로에 없다면 설치된 Playwright 패키지의 절대 경로 지정
$env:YAKEUM_PLAYWRIGHT_MODULE = '<Playwright 패키지 경로>'
# 기본 브라우저는 설치된 Edge의 headless 전용 임시 프로필
$env:YAKEUM_BROWSER_CHANNEL = 'msedge'
node tests/image-review.browser.cjs
```

브라우저 테스트는 일반 `pnpm test`에 포함하지 않아 Playwright가 없는 팀원도 기본 검증을 실행할 수 있습니다. 실제 실행 결과는 `VALIDATION.md`를 참고하세요.

## 개인정보와 남은 범위

가상 제품·성분만 fixture로 사용했습니다. 선택 이미지는 object URL로 브라우저에서만 표시하며 세션 종료 시 해제합니다. 파일명·이미지·수정 내용을 로그나 localStorage에 남기지 않고 이미지 검토 API 요청도 하지 않습니다.

이번 지시서의 Mock UI 범위는 구현·검증 완료입니다. 실제 AI 연결·사용자 수정 저장·정규화 후 비교·권한 인증·DB·배포는 별도 통합 범위입니다. 원본의 로컬 미리보기와 파일 오류·교체 복구도 가상 PNG로 검사했습니다. 후보 검토 화면은 390px을 포함한 headless 브라우저 및 키보드로 검증했으며 실제 모바일 기기와 전체 스크린리더 검증으로 확대 해석하지 않습니다.

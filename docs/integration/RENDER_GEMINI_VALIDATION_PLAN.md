# Render 합성 약봉투 Gemini 검증 준비

2026-10-30 (한국 시간). 시작 코드 `595e77f7e043e9f2b3491ec5024c37c6c38d6f3c`.
이 문서는 실행 승인이 아니다. 이번 실제 Gemini·식약처·모델 조회 0회, 설정 변경·배포 없음.

## 새로 확보한 증거

사용자가 Render에서 **HIRA 실제 식약처 매칭 → 비교 → 저장 → 재조회**를 직접 확인했다고 보고했다.
출처는 이번 대화의 사용자 수동 확인이다. 실행 시각·제품·전체 응답·배포 SHA는 이번 보고에
없으므로 임의로 추가하지 않는다. 개발자가 재호출/브라우저 재현한 증거로 바꾸지 않는다.
이는 앞선 관리자 조회(7건 중 3건)와 다른 기능 검증이다. 모든 제품의 함량 정확성이나 운영 보안을
보장하지 않는다. 기존 관리자 1회 소비 기록은 변경하지 않는다.

## 시험 자료·기대값

[samples/render-gemini/synthetic-bag.png](samples/render-gemini/synthetic-bag.png):
800×500 PNG. 이전 합성 시험 자료를 그대로 재사용하며 사진 편집이나 실제 환자 자료를 사용하지 않는다.
그림에 가상 시험/실제 처방 아님을 명시했다. 같은 파일을 이전·현재 두 칸에 사용한다.

- 제품명 가상알파정 / 성분 가상알파성분 / 성분 함량 100 mg
- 1회 2 정 / 하루 2 회 / 7 일
- 후보 1개, 최초 user_confirmed=false. confidence는 정확도 보장이 아니다.
- 비교 기준일은 이전 2026-09-01, 현재 2026-10-01을 화면에서 지정한다.
  날짜는 이미지에서 추정하지 않고 요청 문서의 기준일로 전달한다.
- Mock 공식 목록의 가상알파정(100mg)과 대응한다. 이 가상 성분을 식약처에 조회하지 않는다.

## Render에서 사용자가 나중에 확인할 설정

현재 클라우드 개발 환경의 키 등록은 Render 등록을 뜻하지 않는다. Render 설정을 직접 읽거나 변경하지 않았다.
Render Dashboard → yakeum 서비스 → Environment에서 **승인 후** 다음을 확인한다.

| 서버 변수 | 준비값/확인 |
|---|---|
| GEMINI_API_KEY | 해당 프로젝트 키를 Render 비공개 값에 입력. 채팅·스크린샷·로그·VITE_*에 넣지 않기 |
| YAKEUM_GEMINI_MODEL | 앞선 1회 성공 기록의 `gemini-3.5-flash-lite`가 후보. 현재 계정 사용 가능 여부/요금은 미재확인 |
| YAKEUM_GEMINI_LIVE_ENABLED | 실행 승인 전 0 유지, 승인된 시험 때만 1 |
| YAKEUM_GEMINI_LIVE_MAX_REQUESTS | 두 사진 전체 시험 승인 시 2. 현재 기본값 1이면 두 번째 요청은 429 차단 |

모델 목록 조회는 하지 않는다. 사용자는 AI Studio 모델/할당량과
https://ai.google.dev/gemini-api/docs/pricing 에서 계정의 현재 무료/유료 단가를 확인한다.
기존 1회 성공이 현재 Render 계정·모델 권한을 증명하지 않는다. 비용은 입력 이미지·프롬프트 토큰 및
출력(요청당 최대 4096 토큰)과 계정 단가로 결정되므로 무료를 보장하지 않는다.
기존 DB/인증/쿠키/MFDS 설정은 그대로 둔다. 설정 적용·배포·실제 요청은 별도 승인 대상이다.

## 정확한 클릭 순서와 호출 수

1. 로그인 → 가상 가족 선택. **실제 식약처 매칭 요청 체크 해제** 확인. 이 단계 Gemini 0/MFDS 0.
2. 현재 사진에 위 PNG 선택, 현재 기준일 2026-10-01, 자료 유형 약봉투 선택.
3. 사진 업로드 전체 연결 영역에서 이전 기준일 2026-09-01, 이전 사진에 같은 PNG 선택.
4. 사진 추출 방식을 Gemini로 선택. 모드/파일/날짜/가족을 바꾸면 기존 후보가 초기화되므로 먼저 설정한다.
5. 이전 영역의 `Gemini로 사진 추출 요청`을 **한 번** 클릭: Gemini +1/MFDS 0.
   기대값과 대조한다. 실패/시간 초과/응답 불명확이면 여기서 중단, 재시도하지 않는다.
6. 성공하면 현재 영역에서 같은 버튼을 **한 번** 클릭: Gemini +1/MFDS 0 (누적 2/0).
   최초 사용자 미확인 상태와 기대값을 확인한다. 실패하면 중단한다.
7. 양쪽 후보 내용을 대조하고 필요하면 수정, 원본과 수정 표시 확인 → 확인 체크 →
   각 `추출 내용 확인 완료 (로컬)`. 실제 복용 확인과 다르다. 외부 호출 0.
8. `수정 후보 B 정규화 미리보기` → 출처/정규화 검토 → `정규화 결과 확인 후 D 비교`.
   같은 내용이면 `＝ 기록 동일`. 누락·실패·함량 미확인이 남으면 보류 사유와 원본을 확인한다.
   추측해 성공을 만들지 않는다. 이 계획의 정규화·비교는 Mock 매칭으로 외부 호출 0.
9. 실제 복용 여부를 별도로 선택 → `확인한 결과와 복용 선택 저장` → 저장 목록 새로고침 →
   저장 결과 열기 → 출처/별도 복용 상태/이전·현재 변경 이력 확인. 로그아웃·재로그인 후 재조회.
   외부 호출 0. 보류 사진은 현재 계약에서 확정 결과 저장 대상이 아니므로 보류 원인 검토 후 중단한다.

**정상 완주 총 Gemini 최대 2회, 식약처 0회, 모델 조회 0회, 자동 재시도 0회.**
한 장 인식만 먼저 승인하면 5번까지만 Gemini 1회이며 전체 비교·저장은 아직 검증하지 못한다.
한 이미지를 두 번 추출하는 것은 두 호출이다. 실제 식약처 체크를 켜는 계획으로 바꾸면 이 호출표를
사용하지 않는다(미리보기/비교가 각각 별도 공식 조회를 실행할 수 있음).

## 호출·화면 보호의 실제 한계

- 각 후보 패널 pending ref + loading 버튼 비활성화로 연속 클릭을 막는다.
- SDK timeout=60000ms, retry attempts=1, 요청 hook 1회 제한. 서버 실패 시 Mock 대체 없음.
  60초는 SDK I/O 제한이며 프록시/업로드/전체 화면의 절대 완료 시간 보장이 아니다.
- 서버 Lock으로 단일 프로세스 동시 요청 예산을 보호한다. 실패/시간 초과도 예산 소비.
  **DB에 보존되는 전역 예산/중복방지 기능은 아니다.** 재시작·여러 프로세스·여러 탭의 재요청은
  별도 호출 가능성이 있다. 관리자 MFDS 검증의 DB 1회 장치와 혼동하지 않는다.
  한 탭·단일 worker에서 순서대로 실행하고 실패 시 재시작/재클릭으로 우회하지 않는다.
- 취소/가족 변경은 AbortController와 요청 세대로 늦은 응답 표시를 차단한다.
  이미 시작한 서버 추출/비용은 취소되지 않을 수 있다. 취소 후 새 요청은 별도 승인 필요.
- 추출 출처는 이전/현재 `Gemini 추출`, 의약품 매칭은 `가상 의약품 매칭`으로 별도 표시하고
  저장 후에도 snapshot 출처를 유지한다. GEMINI 경로도 테스트 harness에서는 가짜 전송이므로
  출처 문자열만으로 실제 외부 호출 증명으로 삼지 않는다.

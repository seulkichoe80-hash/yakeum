# 배포 후 수동 점검 반영 — 모바일·날짜·출처·HIRA 대기

2026-10-29 한국 시간. 시작 codex/mvp-completion / 7b0887db233732d9d65e5c94605d069fe07ddf61.
전체 원격 fetch 후 origin과 일치, clean. 기존 작업·브랜치/DB 자료 보존.
사용자는 해당 배포에서 재시작 뒤 가족/사진 저장 복원, 모바일 로그인/저장 결과 열기를 확인했다고 보고했다.
이는 사용자 제공 결과이며 이번 Codex의 실제 Render/실제 기기 재검증을 뜻하지 않는다.

## 변경 내용

- 계정 영역의 가족 추가/선택·사진·기준일·자료 유형 등 라벨-입력 쌍을 세로 배치.
  입력 min-width:0/max-width:100%, 버튼 여백·줄바꿈으로 좁은 화면 잘림/겹침 방지.
- 사진/HIRA 저장 목록과 삭제 확인의 ISO 시각을 Asia/Seoul, 24시간 `2026.10.28 18:44` 형식으로 표시.
  서버 저장값·API·JSON 원본은 바꾸지 않음. 시간대 없는 날짜는 임의 변환하지 않음.
- 추출 출처 MOCK는 '가상 추출', 공식 LOCAL_MOCK 표시는 '가상 의약품 매칭', GEMINI는 'Gemini 추출'.
  기존 코드 enum과 Gemini 요청 경로/실제 호출 검증 구분은 유지. 가상 결과 안내를 제거하지 않음.
- HIRA 안내의 '로컬 SQLite', 사진의 '로컬 DB' 고정 문구를 개발용 DB로 수정. SQLite/PostgreSQL 모두 대응.
- HIRA의 기존 fetch는 제한 시간이 없어 응답이 끝나지 않으면 busy가 유지될 수 있었음.
  실제 서버에서 길어진 요청의 원인을 확정한 것은 아님. 10초 지연 안내/60초 UI 대기 종료를 추가.
- 성공/실패/취소/타임아웃 때 busy·삭제 대기·지연 안내 정리. 가족 변경/언마운트/새 요청 시 타이머 정리.
  요청 세대·AbortController로 취소/늦은 응답이 결과를 다시 표시하지 않도록 유지.
- 저장 응답 누락/취소/시간 초과는 실패 확정이 아니라 '완료 여부 확인 필요'로 처리.
  저장을 다시 보내지 않고 GET 저장 목록/상세에서 해당 run을 찾는다. 실제 저장이 확인될 때만 해제한다.
  목록에 없다고 아직 처리 중일 수 있는 저장을 무조건 다시 보내지 않는다. 자동 재시도/재저장 없음.
  조회로 끝내 확인되지 않으면 저장 버튼은 보수적으로 막힌 상태이며, 자동 재전송 해제는 구현하지 않았다.

DB/백엔드·SSL·계정/가족 권한·비교/복용 의미·공통 Schema/API를 변경하지 않았다.
시간 초과/화면 취소는 이미 전송된 서버 작업을 되돌린다고 보장하지 않는다.
실제 Render 재배포/실제 건강정보 업로드/실제 Gemini·MFDS 호출은 하지 않았다.

사진/HIRA 목록의 한국 시간 표시와 원래 API ISO 값, 가상 출처 표시를 각각 검사했다.
성공/503 실패/명시적 재시도/취소·늦은 응답 차단을 확인했다.
Playwright clock으로 10초 지연 안내/60초 종료를 검사하고, 저장은 서버 완료 후 응답만 늦추거나 취소했다.
그 뒤 GET으로 저장을 복구하고 저장 POST가 한 번뿐임을 확인했다.
서버에 저장되지 않은 경우에도 자동 재전송이 없고 GET 확인만 하는 것을 검사했다.
계정/가족 분리·로그아웃·저장/삭제·HIRA 정상/보류/0건·원본/수정·별도 복용 유지 검사 통과.
Gemini 검사도 MockTransport 가짜 전송 9회뿐이며 실제 API 요청 0회. 런타임 오류 0.
기존 provenance 문자열 검사는 새 사용자 표시 문구에 맞췄고 원본 source enum 형식은 변경하지 않았다.

백엔드·DB 코드는 바꾸지 않아 기존 전체 백엔드/원격 DB 검사를 불필요하게 반복하지 않았다.
실제 Safari/휴대전화·배포 후 브라우저 검사는 미실행이며 사용자의 수동 재확인이 필요하다.
Render 재배포는 사용자가 별도로 수행한다.

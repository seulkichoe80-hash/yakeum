## 핵심 변경

- 상단 약이음/가족 선택/핵심 메뉴. 가족 추가·매칭 설정·관리자 검증은 관리로 이동.
  저장 상세에서는 다음 처리 설정을 숨긴다. 기존 로그인·로그아웃은 계정 메뉴로 제공한다.
- 사진은 등록/내용 확인/결과 3단계. 계정 화면만 AccountPhotoFlow를 사용하고
  기존 익명 사진 Mock·업로드 경로는 PhotoWorkflow의 기존 구현을 유지한다.
- 사진 읽기 1회 클릭은 이전→현재 기존 API를 순서대로 실행한다. Gemini는 **최대2회**이며
  실행 전에 표시/동의받는다. 순서를 병렬화하지 않는다. 오류/FAILED·확인필요 후보/취소/65초 대기 초과는
  다음 요청을 중단한다. 성공한 쪽의 문서/후보 snapshot은 재사용한다. 재시도는 자동 실행하지 않는다.
- Gemini의 지정 PNG/서버 관리자/영속2슬롯/일반LIVE_ENABLED=0 보호는 그대로다.
  소비한 슬롯인데 결과가 없으면 설명하고 재호출을 막는다. 새로고침 전 기록은 기존 API에
  상태조회가 없어 사전 판정할 수 없지만 서버409 후 즉시 UI를 잠그고 다음 요청도 하지 않는다.
- 내용 확인은 양쪽 원본 이미지/핵심 입력을 함께 보여주고, 성분·기간·추가 정보는 펼쳐 수정한다.
  단일 원본 대조 동의를 받은 뒤 기존 후보별 reviewReducer/draftIssues를 그대로 적용한다.
  FAILED/record:null/입력 오류/확인 보류가 하나라도 남으면 배치 확정을 거부한다.
  원본 user_confirmed=false는 보존하며 사용자가 확인한 draft만 기존 API로 보낸다.
- 내용 확인하고 비교는 미리보기(false)를 먼저 실행한다. MATCHED이고 warnings/errors가 모두
  없을 때만 기존 최종 확인(true)을 순차 실행한다. 사용자 동의문에 경고가 없으면 비교까지 진행함을
  명시한다. 경고/일부 확인은 자동 진행하지 않고 보완값·경고를 보여준 뒤 별도 동의를 받는다.
  보류는 정상0건으로 바꾸지 않는다. 실제 MFDS 선택 시 이 두 처리 단계는 최대2회의 별도 조회임을 표시한다.
- 결과에는 가족·확인된 기준일·4개 상태 수 또는 보류 사유 수, 약 이름/배지/주요 투약 정보/굵은 차이를 우선한다.
  보류 수는 약 개수를 추정하지 않고 **서버 보류 사유 건수**로 명확히 표시한다.
  성분/비교표/기간/원본/JSON/진단은 펼침. 날짜·기간과 판정 기준이 별개라는 안내를 유지한다.
- 복용 상태는 라디오 선택이고 미선택과 명시적 UNKNOWN을 구분한다. 신규 저장은 하단1개,
  과거 저장 변경은 변경사항 저장1개다. 카드마다3개 저장 버튼을 두지 않는다.
- HIRA 파일 선택→기록 비교하기→결과. 업로드 선택만으로 조회하지 않는다. 기존 초안 복구는 보조 펼침으로 유지.
- 저장 목록과 상세는 교대 표시한다. 목록으로 돌아가면 행 포커스/스크롤 위치를 복원한다.
  탭 이동은 컴포넌트를 유지하며 네트워크를 실행하지 않는다. 가족 변경/로그아웃은 작업을 폐기하고
  AbortController/세대 검사를 통해 늦은 응답이 다른 가족을 표시하지 못하게 한다.

## 저장과 부분 실패 처리

사진/HIRA 기존 save API 모두 intake_confirmations 배열을 한 DB 트랜잭션에서 처리할 수 있다.
이를 재사용해 결과와 명시적으로 선택한 복용 상태를 1개의 POST에 묶었다. 여러 PATCH로 쪼개지 않는다.
미선택은 payload에서 제외하므로 확인 전 상태를 사용자 확인으로 만들지 않는다.

POST 성공 후 조회가 실패하거나 POST 응답이 불명확하면 전체 성공으로 표시하지 않는다.
저장 버튼/복용 변경을 잠그고 GET으로 확인한다. **자료가 존재한다는 사실만으로 선택한 상태까지
저장됐다고 하지 않는다.** 요청한 모든 선택의 값과 USER_VERIFIED를 대조한다.
미확인이 남으면 자동 재전송하지 않는다. 같은 run을 다시 열어도 확인 대기 선택을 보존한다.
삭제는 보조 펼침 안에 두되 기존 삭제 대상 확인/취소/소유권 API를 그대로 유지한다.

## 화면 변경

- 사진으로 비교/HIRA로 비교/저장 기록 탭. `hidden`으로 표시만 변경하고 컴포넌트는 유지한다.
  탭 이벤트에는 API 호출 없음. 파일·날짜·후보·작업 결과 유지. 가족/매칭 모드 변경과 로그아웃의
  기존 remount/AbortController/세대 검사는 유지한다.
- 사진 4단계 상태, 이전/현재 기준일, 이전 후보 확인 후 현재 제목 이동 버튼.
  추출/비교 완료 제목은 현재 보이는 작업에서만 포커스한다. HIRA도 요청 시작 탭과 완료 탭을 대조한다.
- 파일/기준일/합성 동의가 없으면 추출 비활성 및 인접 사유 표시. 완료 후 확인 폼을 우선한다.
  가상 재추출은 접힌 보조 영역, 실제 Gemini 재시도는 권하지 않는다.
- 합성 요청을 이미 시작한 슬롯을 가족/파일 변경 뒤에도 같은 로그인 작업에서 다시 제출하지 않는다.
  실제 제한의 판정은 변경하지 않은 서버/DB이다. 관리자 MFDS 검증은 별도 펼침 영역,
  Gemini 동의도 관리자 검증 영역으로 구분한다.
- 내부 B/D 용어를 사용자 버튼에서 제거. 원본 대조 확인과 의약품 보완값/경고 검토는 별개 단계.
  비교 전 보완된 성분·함량·투약 정보와 중요한 경고를 JSON 없이도 표시한다.
- 공통 RecordSummary를 사진/HIRA 처리·저장 화면에서 재사용. 명시적 null은 기록 없음,
  undefined는 기록 확인 필요, 존재하는 필드 누락은 미확인. 보류는 정상 0건으로 바꾸지 않는다.
- 비교 카드에서 약 이름/기호 배지/굵은 이전→현재 변경, 성분/함량/투약량/단위/횟수.
  PC 두 열, 좁은 화면 한 열. 날짜·기간은 별도 표시, 실제 복용 상태도 별도 제목.
- 처리 출처와 저장 상태, 사진 저장 후 저장한 결과 보기. 사진 목록 새로고침도 현재 상세를 유지.
  기존 HIRA 초안 GET 복구/저장 불명확 시 상태 조회/삭제 확인은 유지한다.
- 최신순 서버 목록을 카드 목록으로 표시. 상세를 실제 읽은 항목은 응답에 근거한 출처를 표시한다.
  JSON/부가 설명은 펼침으로 제공하되 보류/오류/주요 경고는 화면에 남긴다.

## API를 바꾸지 않아 남는 표시 한계

- 목록 API는 id/created만 제공한다. created는 처리 자료 생성 시각이며 별도 저장 완료 시각이 아니다.
  이를 **처리 시각(한국 시간)**으로 표시한다. 정확한 저장 완료 시각을 새로 만들어 표시하지 않는다.
- 목록에 없는 출처는 상세를 열기 전에는 ‘출처는 결과를 열어 확인’이다. 오래된 순수 Mock 사진 결과에는
  extraction_sources가 없을 수 있다. 이때 사진 출처 확인 필요로 표시하며 mode만으로 AI 출처를 추정하지 않는다.
- MFDS_LIVE는 실제 요청 경로다. 성공 개수는 status=MATCHED + source=MFDS_DRUG + official_id가 있는
  정규화 응답만 집계한다. 요청 경로 표시는 개별 제품 매칭 성공 보장이 아니다.
- 기존 API에 합성 슬롯 상태 조회가 없다. 현재 로그인 작업에서 직접 시작한 슬롯은 UI에서 차단하지만,
  새로고침/재로그인 전 서버 소비 기록을 화면이 사전에 조회할 수는 없다. 동의가 실행 가능 보장이 아님을
  표시하며, 기존 고정 DB 슬롯/409 재실행 차단은 유지한다. 초기화/추가 호출은 하지 않았다.
- HIRA는 기존 계약대로 결과 저장 후 별도 복용 상태를 저장한다. 사진은 저장 전에도 선택할 수 있다.
  저장을 복용 확인으로 취급하지 않는다. 사진 보류 저장 정책을 확장하지 않았다.

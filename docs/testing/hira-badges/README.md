## 먼저 이렇게 실행하세요

1. 배포 화면에 접속해 시연 입구와 개발용 계정으로 로그인하고, 가상의 가족을 선택합니다.
2. 해당 가족의 **HIRA 자료 비교·저장** 영역을 엽니다.
3. 아래에서 한 사례 폴더를 고르고 **previous.xlsx는 이전 HIRA 파일**, **current.xlsx는 현재 HIRA 파일**로 선택합니다.
4. **HIRA 파일 처리**를 누릅니다. 서로 다른 폴더의 파일을 섞지 마세요.
5. 배지·이전/현재 값·비교 실행 여부·복용 확인을 확인합니다. 비교만 볼 때 저장 버튼을 누를 필요는 없습니다.
6. 다음 사례도 이전·현재 파일을 모두 교체한 뒤 처리합니다. 처리 중이면 취소하거나 완료를 기다립니다.

로컬 시연은 앱 실행 안내를 따르세요. 자료에는 계정/비밀번호/API 키가 없으며, 임의 계정의 자료를 읽지 않습니다.
이전/현재의 뜻은 파일 역할입니다. `이전에만 있음`은 기존 저장 기록을 삭제하거나 복용을 중단하는 명령이 아닙니다.

03/04의 빈 자료는 **손상 파일이나 0바이트 파일이 아니라 제목·헤더가 있는 유효한 XLSX**입니다.
행을 새로 채우거나 빈 파일을 생략하면 최소 사례와 다른 결과가 됩니다.

## 놓치지 말아야 할 구분

- 다섯 상태 모두 현재 HIRA 입력으로 재현됐으므로 사진 Mock으로 억지 대체할 필요가 없습니다.
- `NEW`: 과거 자료에 없던 현재 **기록**입니다. 신규 처방·복용 시작·안전성 확정이 아닙니다.
- `NEEDS_CONFIRMATION`: 현재 자료에서 대응 기록이 확인되지 않는다는 뜻입니다. 복용 중단이 아닙니다.
- `HELD`는 별도 Reconciliation 상태를 새로 만든 것이 아니라 비교가 미실행됐다는 화면 표시입니다.
- 보류: comparison.executed=false, reconciliation_result=null, 보류 이유·원본 두 행 유지.
- 정상 비교 0건: comparison.executed=true, reconciliation_result.items=[]. 보류와 다릅니다.
- 유지/변경/신규/이전에만 있음 결과의 실제 복용은 처음에 **잘 모르겠음 · 확인 전**이어야 합니다.
  별도 복용 버튼을 선택하기 전에는 자동 확정하지 않습니다. 보류에는 새로운 복용 확인 항목이 없습니다.
- 색은 기록 차이이며 의료적 안전·위험 판정이 아닙니다. 유지도 날짜/기간/메모 전체 동일을 보장하지 않습니다.

파일에는 제품명 `가상제품`과 기존 가상 카탈로그용 코드 문자열 `000123456`을 넣었습니다.
현재 LOCAL_MOCK 매칭 후에는 화면에 `타이레놀정500밀리그램 / 500mg`으로 보일 수 있습니다.
이는 기존 테스트 카탈로그를 사용한 가상 매칭 결과이며 실제 식약처 조회나 실제 복용 자료가 아닙니다.
코드를 숫자로 바꾸거나 앞의 0을 지우지 마세요. 성분/함량 칸을 추측해서 새로 채울 필요도 없습니다.

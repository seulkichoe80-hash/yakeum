# 약이음 가상 자료 사용자 시험 안내

상태: **준비 완료, 실제 사용자 참여 시험은 아직 미실시**. 자동 브라우저 검사를 실제 사용자 평가로 합산하지 않는다.
대상: 팀원/외부 시험자 5~20명, 가상 계정·가상 자료만 사용, 1인 약 15~20분.
참여자에게 메시지를 보내거나 모집을 실행한 것은 아니다.

## 진행자 준비

1. DEV_ACCOUNT_STORAGE_V1.md의 개발 설정을 적용한다. 별도 시험용 SQLite 경로를 지정하고 기존 개발 DB와 섞지 않는다.
2. 아래 명령으로 소스 저장소 밖의 빈 폴더에 시험 자료를 생성한다.

```bash
python scripts/create_synthetic_test_kit.py --output /tmp/yakeum-user-test-kit
```

3. 파일: synthetic-photo.png(가상 이미지), previous.xlsx(이전), current.xlsx(정상 현재), held.xlsx(실패행 포함), empty.xlsx(정상 0건).
4. 진행자가 먼저 정상 경로를 점검하고 시험자가 접속할 수 있는 개발용 주소를 제공한다.
   127.0.0.1 주소는 서버가 실행되는 컴퓨터 안에서만 열린다. 클라우드 주소를 자동 공개한 기능은 없다.
   승인된 내부 접속 수단이 없으면 시험자의 PC에서 개발 앱을 실행한다. 운영 배포·공개 게시를 뜻하지 않는다.
5. 같은 IP의 가입/로그인은 10분당 각각 10회 제한이다. 공용 네트워크에서는 3명씩 시작을 10분 이상 나누고,
   재로그인 횟수/오입력을 고려한다. 제한을 낮추지 말고 대기한다. 자동 검사 서버와 사람 시험용 DB도 분리한다.
6. 참여자는 평소 쓰는 비밀번호·실명·건강정보를 쓰지 않는다. 피드백에는 P01~P20 같은 참여 코드만 사용한다.
   비밀번호/세션/DB 파일을 채팅·설문·GitHub에 올리지 않는다.

## 참여자 과제

진행자는 처음에는 클릭 위치를 알려주지 않고 어디서 막히는지 기록한다.
도움을 줬다면 완료 여부와 별도로 '도움 있음'을 남긴다. 오류 장면도 기록하며 성공으로 바꾸지 않는다.

### A. 사진 정상 결과 (약 6분)

1. 첫 화면 상단 '개발용 로그인·저장 열기'. test_p01 같은 가상 아이디로 가입/로그인.
2. 가상 가족 A, 가상 가족 B를 추가하고 A 선택.
3. 현재 사진으로 synthetic-photo.png 선택. 이전 사진에도 같은 파일 선택.
4. 이전/현재 각각 '사진 업로드 후 가짜 후보 보기'. 현재 후보 1회 투약량을 1에서 2로 수정.
5. 원본 대조 체크와 '추출 내용 확인 완료'. 정규화 미리보기 → 결과 검토 후 D 비교.
6. 실제 복용 여부는 별도 단계임을 확인하고, 모르면 선택하지 않은 상태로 저장해 본다.
   저장 목록에서 '잘 모르겠음 / 확인 전'인지 확인한 뒤 명시적으로 복용 여부를 선택해 저장해 본다.
7. 로그아웃 → 재로그인 → 가족 A의 저장 결과 다시 보기. 원본 1과 수정값 2가 분리되어 있는지 확인.
8. 삭제 안내를 열고 대상 가족·사진·저장 시각·함께 지워지는 정보를 읽은 뒤 한 번 취소.
9. 결과가 유지되는지 확인하고, 다시 삭제 확인. 목록 새로고침/재접속 시 사라지는지 확인.

사진의 글자를 실제 AI가 읽는 시험이 아니다. 업로드/수정/확인/저장 동작은 실제 로컬 코드지만
후보는 가짜 AI 응답이고 공식 매칭은 Mock이다. 실제 의약품 정확도를 평가하는 자료로 사용하지 않는다.

### B. HIRA 정상 결과 (약 4분)

1. 'HIRA 자료 비교·저장'에서 이전 previous.xlsx / 현재 current.xlsx 선택 → 파일 처리.
2. 원본·정규화·비교 결과를 열어 본다. '저장'과 '실제 복용 확인'이 같은지 설명해 본다.
3. HIRA 결과 저장. 실제 복용 여부는 별도로 선택해 저장한다.
4. 로그아웃/재로그인 후 다시 보기. 가족 B에는 A의 결과가 없는지 확인.
5. 저장한 정상 HIRA를 삭제한다. 사진 자료가 함께 사라지지 않는지 확인.

### C. 보류와 0건 (약 4분)

1. 이전 previous.xlsx / 현재 held.xlsx 처리. 보류 이유와 실패 원본 행을 확인하고 보류 상태로 저장.
2. 저장 목록에서 다시 보기. 비교 결과나 복용 확인이 임의로 생기지 않는지 확인.
3. 삭제 안내 → 취소 → 유지 확인 → 다시 삭제.
4. 이전/현재 모두 empty.xlsx 처리·저장. '비교 완료 · 결과 0건'과 '비교 보류 · 비교 미실행'의 차이를 설명해 본다.

### D. 화면/취소 (약 2분)

휴대전화 또는 좁은 화면과 PC에서 파일 입력·안내·삭제 버튼을 읽고 누를 수 있는지 확인한다.
처리 취소·가족 변경·로그아웃 후 이전 결과가 다시 나타나는지 관찰한다. 삭제 확인을 누르기 전 취소하면 데이터는 유지되어야 한다.
삭제 요청을 이미 보낸 뒤의 서버 완료는 화면 취소로 되돌릴 수 없으므로 목록으로 최종 상태를 확인한다.

## 종료 질문 (예/아니오 + 이유 또는 1~5점)

1. 사진 내용 확인과 실제 복용 여부 확인의 차이를 알 수 있었나요?
2. 비교 보류와 정상 결과 0건을 구분할 수 있었나요? 각각 무엇을 뜻하나요?
3. 저장한 자료를 가족별로 다시 찾기 쉬웠나요? 어디서 막혔나요?
4. 삭제할 자료와 함께 삭제되는 내용을 안내만 보고 알 수 있었나요?
5. 삭제 취소·삭제 완료 후 화면은 예상과 같았나요?
6. 휴대전화에서 읽기 어렵거나 누르기 힘든 글자·버튼이 있었나요?
7. 가장 어려운 문구 하나와 쉬운 대체 문구를 제안해 주세요.
8. 도움 없이 다시 사용할 자신감은 1~5점 중 몇 점인가요?

## 기록과 판정

user-feedback-template.csv에 참여 코드·기기·과제·도움 여부·시간·막힌 부분만 기록한다.
실제 계정 비밀번호/실명/건강정보/DB/원본 개인정보는 수집하지 않는다. 화면 캡처도 가상 정보만 포함한다.
도움 없이 완료/도움 후 완료/미완료를 구분하고, 오류 재현 순서를 남긴다.
시작 전 운영 정책이나 합격 비율을 임의로 확정하지 않는다. 결과가 모이면 막히는 문제부터 수정하고 재시험한다.
실제 참여자가 없을 때는 '시험 준비/자동 검사 완료'까지만 보고한다.
